# MvcBookshelf

## Week 15
A stored procedure was added through the SQL Server Object Explorer in the MVCBookshelfContext in Programmability > Stored Procedures. The procedure “GetMostPages” was created and selected the [Pages] column from the Book table to select all of the Page attributes of each Book object found in the table. To accommodate for the stored procedure and it’s purpose, task GetMostPagesAsync was created in interface IBookshelfService.cs. In BookshelfService, GetMostPagesAsync was defined to hold a variable called query, which would utilize the Database.SqlQuery method of int type, executing the GetMostPages stored procedure in string interpolation and then holding the results as a list using ToListAsync. This created a list of the int values found in the Book table’s Pages column. The task would then return the Maximum value found in query’s list using Max(). StatisticsViewModel included the attribute MostPages to hold the value as an int. In Views > Books > Statistics.cshtml, another table header column was created for “Highest Page Count”. Another table data row was created to hold the model’s value for Most Pages from StatisticsViewModel. In BooksController in Statistics with the existing StatisticsViewModel, the value for the model statsViewModel.MostPages was created and set to GetMostPagesAsync() to properly updated the model’s value in the controller. Therefore, the view of Statistics.cshtml would include the result of MostPages, as the maximum of a list of integers gathered from the Pages column in the Book table. 


## Week 14
Logging was reinforced and added to the project. In BooksController, an instance of ILogger was created and included in the controller constructor. The index includes parameters for a string of sortOrder and a string of searchString. When the user selects the columns for sorting, _logger.LogInformation will log basic description of the desired sort. If a user selects the Author column, it will utilize OrderBy on the Author attribute. Another LogInformation is used when searchString is not null, and logs that the searchString is being compared to results in the Title or Author attribute. For the Statistics class, each call to Get(Books/Authors/Genres/Pages)Async includes a LogInformation method denoting which method is being used and set to the appropriate variable in the created statsViewModel object. Additionally, the Details task logs the field for BookID as well as the id requested. The Create method logs information for its CREATE GET action. The post action task for Create will log an error path if the ModelState is not valid (without the binding ID, Title, Author, Genre, Rating, or Pages), denoting a LogWarning that the CREATE POST model was invalid. Similarly, the Edit method logs information for its EDIT GET, and the post action task for Edit will also create a LogWarning if the denoted ModelState is not valid. Finally, the Delete task logs the deleted id, including the POST Delete task. In Program.cs, logging was added for initializing the seeded data and when the application is ran.

## Week 13
The Secret Manager tool was enabled at the project directory and a secret with the key "MvcBookshelf:ServiceApiKey" was created with a set value. This secret is found in the project by selecting [Manage User Secrets]. This secret can be read through the Configuration API in Program.cs with the variable 'mvcBookshelfSecret'. The code to access and read this secret was commented out to allow for the program to run, but the secret is accessed through app.MapGet("/", () => mvcBookshelfSecret);. To implement a healthz endpoint into the project, an appropriate NuGet package was installed to access the health check using entity framework core: Microsoft.Extensions.Diagnostics.HealthChecks.EntityFrameworkCore. This NuGet package was the best option as a custom health check is not necessary to be registered as the Entity Framework Core DbContext probe can register the context as well as the health check. The created SampleHealthCheck.cs class is therefore redundant and is not used. The previous AspNetCore.HealthChecks.SqlServer package was also not used. Once installed using the NET 9.x version and not the incompatible 10.x version, the health check can be added using Services.AddHealthChecks().AddDbContextCheck<MvcBookshelfContext>();. After mapping the API endpoint into the app at "/healthz", running the app and entering healthz into the URL returns a Healthy result, showing that the health check for the Entity Framework Core DbContext probe returned a successful health check on database connection.

## Week 12
For implementing CRUD, many of the asynchronous CRUD features were already created in the project. In BookshelfService.cs in the Services folder, the task GetAllAsync() awaits the database, retrieves the Book table, and retrieves all of the Book objects as a list using await _db.Book.ToListAsync(). Another example of asynchronous methods in BookshelfService is Task AddAsync, which adds a book object to the Book table and then saves this change asynchronously to the database using await _db.SaveChangesAsync(). For the Statistics page, the Task GetTotalAuthorsAsync() will return the total author database results by awaiting the database, utilizing async LINQ operators of .Select to select only the authors in the Book table, .Distinct for distinct authors, and .CountAsync to count and return the results. Similar async LINQ operators are applied to get the total books, genres, and pages using asynchronous data access methods. Again, many of the validation rules and feedback were already created in the project. These validation rules were further defined, with adding ‘required’ to the Title, Author, and Genre attribute to resolve compiler warning code CS8618 (Non-nullable property must contain a non-null value when existing constructor). Title and Author included a custom error message for denoting the length requirements between 2 and 60. For Genre, regular expression validation was added to ensure the entry would start with a capital and only contain letters. For Rating, proper validation for the int attribute was added to only allow a range of 1 – 5. Verbiage and heading titles were customized to the bookshelf app, including ‘Your Bookshelf’ as the header in Views > Books > Index.cshtml instead of ‘Index’. A css file was created for the Statistics.cshtml view in Books to style the table. This css style was isolated to the Statistics page with the stylesheet’s reference added to the /Shared/_Layout.cshtml page to display only for Statistics.cshtml and not affect the rest of the Books view.



## Week 11
Project was completely remade from Razor pages to MVC with Entity Framework Core. Previous Razor pages project can be found here: https://github.com/chreelee/Bookshelf. Process of remaking the project included installing the EF Core NuGet packages and creating the Book model. The database was seeded with SeedData and a StatisticsViewModel.cs page was also create to display statistics. A new controller, BooksController, was created and scaffolded from the Book model class.
Utilizing MVC, the logic from Statistics and Pages > Books > Indexcshtml.cs was moved to BooksController. Once moved, a services folder was created along with IBookshelfService and BookshelfService. IBookshelfSerice held the asyncronous methods of retrieving, adding, updating, and deleting Book entities. Also added were the methods that used LINQ/SQL to retrieve information for the Statistics page including total: books, authors, genres(that I forgot last week), and pages. Logic from the previous project's statistics.cshtml.cs was moved to BookshelfService. The Statistics page also now includes a genre column that utilizes the GetTotalGenresAsync() method through Bookshelf Service. BookshelfService then held the moved controller's logic for retrieving all of the information using asynchronous methods. Exist and null checking information from the controller was removed for redundancy. The searchString using Where on the queryable collection now properly ignores character cases and allows searching of the searchString in the Title and Author column.



## Week 10
A Book entity was created with attributes of Title, Author, Genre, Rating, and Pages. BookshelfContext was created once the Books page was scaffolded. The DbInitializer was updated to include a migration of Book objects to load into the database. In the Books pages, the database is displayed and the Book entities can be sorted through their attributes. Pages > Books > Index.cshtml provides the sorting options using a default Title sort and ascending and descending sorts for each attribute. A search bar with a searchString was also added to use the IQueryable LINQ method of Where() to search the string in the Title or Author attributes of the Book entities. CRUD actions are available for the Book database. A Statistics page is created in Pages to hold the count of Book entities as Books Completed, the distinct count of Authors as Authors, and the sum of all book Pages as Pages. To create this page, the StatisticsViewModel folder includes a Statistics model. In the Statistics.cshtml.cs, Entity Framework Core methods including Select(), Distinct(), CountAsync(), SumAsync() were used to gather the count and sum of Book entities, distinct Authors, and the sum of all Book entity pages. Once gathered, this information was updated to a new BookStatistics model. Then, this data was displayed in a table in Statistics.cshtml using the page's BookStatistics model similar to Pages > Books > Indexcshtml.cs.
